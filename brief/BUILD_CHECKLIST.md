# Build acceptance checklist

Cursor should check these against the implemented application, not merely against this brief.

- Next.js App Router, TypeScript, React, committed lockfile, and clear local run instructions.
- All five sections appear in order and use one coherent illustrated visual system.
- A newcomer can understand the premise and the short ApeFest explanation.
- The supplied hero and all souvenir/reaction assets load with correct proportions and transparency.
- Desktop and mobile hero framing preserve the ape and suitcase.
- Every history selection updates year, city, fact, joke, art and source together.
- Facts and fictional jokes are distinguishable; initial official links remain attached.
- Every expression/caption combination exports its current composition.
- Rapid changes cannot export an old meme. No wallet/login is needed for this interaction.
- Unknown identity/token/community values stay pending. No dummy address or fake link is active.
- Confirmed contract and pair fields are distinct. Copy has a readable fallback.
- Future image and information updates work through the documented single source files.
- Review 320, 390, 768, 1024 and 1440 px; no horizontal overflow or broken controls.
- Keyboard focus, selected states, accessible names, contrast and reduced motion work.
- Event time is distinct from any token launch time and uses explicit time zones.
- Staging metadata and robots are noindex/disallow; deployment uses the real Preview URL.
- Content/type/test/build checks pass and meaningful interactive review is reported honestly.
- Cursor completion sync commits and pushes only validated work to the supplied staging branch.
- Account/secrets failures preserve the build and identify the precise next account action.
- No production publication, DNS change or main merge occurs during staging setup.
